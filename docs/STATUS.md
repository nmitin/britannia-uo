# Статус проекта

Обновлено: 2026-10-29

## Хронология

1. Ядро POL 100.2.0 склонировано и собрано под CachyOS (GCC 16, C++20).
   - Понадобились два локальных патча сборки (см. `patches/`):
     - `USE_BOOST_HEADER_STACKTRACE=ON` и отключение `-lbacktrace` — в системе нет libbacktrace;
     - сборка curl без libssh2 — иначе статическая libcurl требует libssh2.
2. Развёрнут ModernDistro в `server/`.
3. Клиентские файлы (7.0.x, MUL) скопированы в `client/` из старой установки.
4. Мир Британия сконвертирован: `uoconvert` для multis/tiles/landtiles, map `7168x4096`, statics, maptile.
   - Только Фелукка: в клиенте нет карт Илшенара, Маласа, Токуно и Тер-Мура.
   - Из `regions.cfg`, `startloc.cfg` и `itemdesc` удалены/отключены определения,
     которых нет в клиентских данных (14 регионов, 10 стартовых точек, 888 записей itemdesc,
     7 мульти).
5. Установлены модули eScript из `pol-core/support/scripts`, создан `ecompile.cfg`,
   все скрипты скомпилированы (0 ошибок).
6. Сервер запускается, слушает `2593`. ClassicUO подключается, создаёт персонажа.
7. Проверена кириллица: два сообщения переведены, POL отправил их Unicode-пакетом,
   клиентский журнал сохранил русский текст без искажений.
8. Собран `client/Cliloc.rus` (7 418 строк) из перевода сообщества UOGames (7.0.86).
   ClassicUO загружает его поверх английского `Cliloc.enu`.

  `TestPlayers: Drovosek подготовлен: навыков 3, предметов выдано 2, золота
  выдано 500; в банке 500 золота, в рюкзаке 18 предметов`.
- Грабли POL: `SplitWords(str, delims)` делит по **целой строке-разделителю**,
  а не по набору символов, поэтому `SplitWords(s, "=;")` не работает —
  резать надо последовательно: сначала по `;`, потом по `=`.
  И `CInt("0xF43")` работает (`strtoul` с base 0), но `SplitWords("0xF43","x")`
  разваливает hex на `0` и `F43` — счётчик предметов задаётся через `*`.

## Дополнение: раунд 47 (2026-11-01) — меню капитана и настоящий корабль

- **Кириллица в меню капитана.** Меню направлений делалось через
  `CreateMenu`/`SelectMenuItem2`: этот пакет (0x7C) передаёт строки в CP1252,
  поэтому русские названия городов превращались в `?????`. Меню переписано
  на обычный гумп (`GFCreateGump` + `GFTextLine` + кнопки). Строки гумпов
  лежат в data-массиве, и POL для клиентов 5.0+ отправляет их сжатым пакетом
  0xDD, конвертируя в **UTF-16** (`Bscript::String::toUTF16` в
  `internal_SendCompressedGumpMenu`) — кириллица доходит до клиента.
  Если клиент всё же покажет `?` — виноват рендер шрифта в клиенте, тогда
  меню можно вернуть на латиницу.
- **Корабль в море.** Раньше игрока телепортировало в точку «палубы»
  431–440 x 1499–1508 (436,1504), которая на нашей карте оказалась сушей —
  персонаж «плыл» в горах. Теперь:
  - точка стоянки — открытая вода `1440,1854` (z=-5) юго-западнее Британии,
    найдена по `client/map0.mul` + `client/tiledata.mul` (флаг жидкости 0x80,
    вокруг ≥ 20 тайлов воды);
  - там стоит настоящий корабль — мульти **LargeBoat** (objtype 0x11010,
    MultiID 0x10 из `config/multis.cfg`), создаётся один раз и помечается
    CProp `FerryShip`, повторные плавания его переиспользуют;
  - игрок появляется на палубе (центр мульти: в `config/multis.cfg` первая
    deck-плитка стоит в 0,0,0, поэтому z палубы = z корабля = -5);
  - шагнул за борт рядом с кораблём — его возвращают на палубу, ушёл
    реколлом/гейтом дальше 14 тайлов — поездка отменяется.
- **Почему не работал `CreateMultiAtLocation(...,0x10,...)`:** в ModernDistro
  корабли описаны как `Boat 0x11000+MultiID` в `pkg/multis/itemdesc.cfg`,
  но этот файл не входит ни в один загружаемый пакет, поэтому дескрипторы
  не регистрировались и ядро отвечало `That objtype is not a Multi` /
  `Objtype 0x11010 is not defined`. Добавлен пакет
  `pkg/multis/ferry` (`pkg.cfg` + `config/itemdesc.cfg`) с `Boat 0x11010`.
- Проверено на изолированном стенде (порты 2594/5667/5007): в логе

## Известные проблемы

- Команда `.myform` из seer-пакета может не находиться (unknown command).
  Добавлена надёжная GM-команда `.normalform`: воскрешает персонажа, если он
  мёртв, и возвращает обычное человеческое тело (0x190/0x191). Требуется
  перезапуск сервера после обновления скриптов.
- Клиентский UI (кнопки, окна создания персонажа) в основном английский:
  текст вшит в графику gump'ов, для полного перевода нужна замена gump-арта
  или доработка ClassicUO.
- `Cliloc.rus` покрывает 7 577 строк; все 159 cliloc-ID, используемых сервером, переведены, но в клиентской таблице (~49 700 строк) ещё много английского.
- Часть скриптов ссылается на отсутствующие файлы (`mooringLine.ecl`,
  `housetele.ecl`) — предупреждения при старте, на игру не влияют.
- Три merchant-якоря в `pkg/systems/merchantnodes/backups/nodes.xml` невалидны
  на нашей карте (`2874,662`, `3704,2248`, `3687,2253`) — при старте три
  строки `Unable to create npc ...`. Нужна правка якорей + `WM_VERSION`.
- Сообщение `TS_StartController() - Controller is already running` — безвредный
  варнинг из скриптов.
- Имя сервера в списке — латиницей (`Russian Shard`). Кириллица в пакете
  списка серверов требует проверки.
- Полный список отсутствующих графики/мульти можно получить, сравнив itemdesc
  с `config/tiles.cfg`.
- Имена NPC/предметов/персонажей остаются латиницей из-за CP1252 в пакетах
  имён. Для кириллических имён потребуется патч POL и клиента (Unicode-имена).
